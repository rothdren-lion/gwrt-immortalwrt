# GWRT 无线漫游回传切换（2026-11-19）

从 AP 保留原有配对。主 AP 的发现广播须来自配对地址、带同一配对指纹并从实际回传口进入，
有线还须先获取同网段的 DHCP 租约。确认为主 AP 的网线才会接管；接到其他网络时保留无线。
有线接管前停止 relayd 并等 STA 断开；拔线后先拆除 WAN 桥成员再启动 STA。
有线用桥接，无线用三地址 STA 和 relayd，普通客户端和从 AP 都从主 AP 获取 IPv4 地址。
从主 AP 的 Mesh 拓扑可查从 AP 当前地址；切换时地址可能因租约变化。

两路都断开时默认搜索 120 秒，再恢复从 AP 原先保存的路由配置 60 秒，之后继续搜索。
路由窗口恢复原来的 LAN 地址、SSID、密码及本地 DHCP，保留配对，状态循环不写入持久配置。
设备出厂 LAN 与上游网段冲突时，首次发现可临时改用不同的 LAN 网段。
「无线漫游 → 回传切换」可调整两段时间并查看当前状态、倒计时和管理地址。
旧版与 v5 都去除打赏入口、页面资源和旧菜单缓存。

控制器按状态、链路、网络、无线、迁移、FT 修复拆分；两版守护进程共用
配对状态、主 AP 回传无线和前台 SSID 模块。旧版持久 AP 配置只迁移一次。
详细配置与实机检查步骤见 [GWRT-MESH.md](GWRT-MESH.md)。

## 验证

- 实际 BusyBox 和目标 UCI 的 6 组控制器场景：错线不抢占、插对线切有线、拔线切无线、
  120/60 秒循环、可调时长、保留配对/原配置、首次配对避开同网段、WAN/STA 暂未退出时的保护等。
  增加脱桥前不得启动 STA 的负对照；原候选失败，修正后通过。
- 目标 ARM64 ucode：两版守护进程编译、实际 UDP 入接口元数据、主从回传、
  前台 SSID、时间参数和 FT/客户端回归通过。旧快照、FT socket、SS-01 首启、
  两版打赏资源和菜单清理、自动配对与 29 项 agent 回归通过。
- 隔离网络使用源码树固定版本 `708a76faa7a1f2f62af83303efea0eb760d99c62` 的 relayd：
  有线桥接和无线中继两侧均验证 DHCP；主网和从 AP 侧均可通过从 AP 租约访问测试 HTTP 页面，
  客户端到主网及主网到客户端的流量通过。
- Chrome 在 390px 和 1280px 测试新页的状态、倒计时、参数限制、保存和管理 IP；
  既有 Mesh 发现和配对界面回归通过。
