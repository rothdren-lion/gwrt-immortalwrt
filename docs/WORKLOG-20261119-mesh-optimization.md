# GWRT Mesh 回传优化（2026-11-19）

本次接续 [回传切换改造](WORKLOG-20261119-mesh-backhaul.md)。保持有线优先、
隐藏回传 SSID `mesh-gwrt`、120 秒待命搜索和 60 秒临时路由的默认值。

- 已组网的有线：配对广播超过 16 秒未收到，WAN 载波、掉线计数、桥成员均正常且 DHCP
  租约仍在主 AP 网段时，从 `br-lan` 限时探测主 AP。约 4 秒一次，连续 3 次失败后回退；
  成功探测或收到新广播会清零失败计数。拔线、重新插过、脱桥或租约失效时直接退出。
  新网线与等待桥上 DHCP 的阶段仍使用原配对指纹、入接口和租约验证。
- 无线：验证通过并启动中继后，按实际 STA 接口记录同一配对最后成功的频段。下次搜索
  优先试该频段；不可用或超时后试另一频段。短搜索窗口也给两个频段机会。频段保存在
  `/var/run/gwrt-mesh-apmode/`，不修改持久配置。
- 主 AP 的旧版与 v5 拓扑：点开从 AP，查看有线或无线、无线频段及最近切换原因。
  「打开管理页」使用最近收到状态的已认证 TCP 连接的对端 IPv4。管理地址随回传更新，
  状态过期或连接关闭后隐藏；发现广播及节点上报的 IP 不作为链接目标。

测试使用目标 BusyBox/UCI/ucode、隔离网络和 Chrome。控制器场景覆盖广播漏收、探测失效、
错线、拔插、租约和桥丢失、频段记忆、两个频段的搜索及原路由窗口。两版守护进程使用真实
TCP 对端测试认证、换线换 IP 和过期状态。两版桌面/手机模拟 LuCI 检查链接打开、新地址、
旧链接移除及原因显示。隔离网络验证两种回传上的 IPv4 DHCP、双向流量和管理访问。
