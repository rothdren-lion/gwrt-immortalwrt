# CS-06：261110-01 到 261111-01 的无线启动回退

## 用户确认与结论边界

用户确认 `261110-01`（`d9e8632`，`log-11.10.rar` 对应版本）能够启动
Wi-Fi，但有内存报错；`261111-01`（`486d85c`）内存报错消失，Wi-Fi
却不再出现。应以此作为回归现象，不能因旧日志后期也有固件崩溃而否定
用户观察到的早期启动成功。

先前“内存不足不是这次失败的原因”的说法过于绝对。本次只证明
**CMA 分配失败已消失**，尚未排除扩大 CMA 对 DMA 分配地址、初始化时序
等行为的影响，也未完成相同启动条件下的 16/64 MiB 实机对照。

## 两版真实镜像比对

旧镜像来自 GitHub Actions `42843655189` 的
`gwrt-cs06-261110-01` artifact；提取 sysupgrade ZIP entry 并验证 CRC。
新镜像取自已交付目录
`/home/godsun/build/gwrt-releases/cs06-261111-01/gwrt-cs06-261111-01/`，
对应 Actions `43022297915`。两版均为 Linux 6.18.62、JDCloud RE-CS-06。

| `etc/modules.d` / `etc/hotplug.d` | 163 / 26 个普通文件逐字节相同 |

DTB SHA-256：
`625672e72d5c075b8cf3de7d612e57845493930a322a85983894f3dcbc214fe5`。

两版解压后的 ARM64 kernel Image 均为 19,011,592 字节，仅 120 字节不同。
将 revision、编译日期、两个 GNU build-id 和内置 cpio 的三个时间戳归一后，
只剩一条 AArch64 指令的立即数变化：文件偏移 `0x104e41c`，
`MOVZ x0, 0x1000000` → `MOVZ x0, 0x4000000`，即 16 MiB → 64 MiB。
这与唯一相关源码修改 `CONFIG_CMA_SIZE_MBYTES=16` → `64` 一致。
内核没有嵌入 IKCONFIG，未声称从镜像提取到完整 `.config`。

源码对照 `d9e8632..486d85cb` 中，CS-06 DTS、共享无线 DTSI、mac80211、
固件包、板级数据和 CS-06 配置生成器均未改变。构建时 feeds 没有固定
revision，但上述实际文件比对已排除无线包随 feeds 漂移的可能。

因此，当前证据不支持“新版漏装驱动、换错无线固件或改错 CS-06 设备树”；
应优先验证 CMA 改动与启动条件是否解释启动行为回退。

## 日志能证明的故障顺序

旧日志窗口只有开机 `188.349749–243.278126` 秒，已经是第 5–9 次固件崩溃。
此窗口有 40 条 CMA 分配失败，不能据此还原第一次启动的结果或触发原因。
但旧版可见崩溃前先有 `ieee80211 phy0: Hardware restart was requested`
（`190.383933` 秒）；新版第一次崩溃在 `81.182921` 秒、MLO 首次启动期间，
之前没有硬件重启请求。也就是说两版虽然最终落到同一条固件断言，首次触发
状态不同，符合“旧版曾启动、后因内存压力恢复失败；新版首次 bring-up 就失败”
的用户实测描述。

新日志从开机 0 秒开始：

1. `0.000000`：CMA 预留 64 MiB，整个日志中没有 CMA 分配失败。
2. `74.903890`：Q6 rootPD 启动成功。
3. `78.147321`：AHB 与 PCI 组成两设备 WSI/MLO 组。
4. `79.952450`：两颗芯片均上报 256 ML peer IDs。
5. `81.182921`：AHB 固件报
   `platform_mlo.c:2038 Assertion !partner_chip_crash_ind failed`。
6. `81.256251`：PCI 报 `MHI_CB_EE_RDDM`。
7. `82.945254` 以后：驱动控制命令失败，返回 `-108`；hostapd 随后无法拉起接口。

新日志中共 6 次同一断言；旧日志后期也有相同断言、PC/LR 和固件版本。
两版恢复请求后约 1.18 / 1.22 秒再次崩溃。
这些说明存在共同的固件崩溃表现，但首次触发条件不同。CMA 预留从 16 MiB
增到 64 MiB 是镜像中唯一与硬件行为相关的变化，直接改变了启动时 DMA/CMA
可用地址布局；当前最可疑的回归变量是 CMA 改动引发的早期无线初始化行为变化，
不是固件或驱动漏装。AHB 的 partner-chip 断言与 PCI RDDM 记录仍不足以确认
具体是哪一处 DMA/固件握手先出错，也不能单凭静态镜像差异确定最终根因。
