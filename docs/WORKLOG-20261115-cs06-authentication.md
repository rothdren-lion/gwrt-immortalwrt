## 4. 认证路径的新线索及边界

与前次运行 `261114-01/13bcc6a` 比较，`0580ee9a` 在 mac80211 中只新增了
组恢复/QMI 退出补丁和 release 号；没有更换对应固件包、TX/RX 数据路径补丁、
hostapd 或 wifi-scripts。此次没有实际无线配置，不能排除保留配置、加密方式
或客户端状态的差异，也不能据此宣布恢复补丁引入了首次认证失败。

2026-09-13 ath12k 邮件列表已有原始报告：
[QCN9274 WLAN.WBE.1.6 firmware drops EAPOL msg3/4 and asserts in wal_tx_de_mgmt.c with TX encap offload](https://lore-kernel.gnuweeb.org/ath12k/aqFARFlTS7757Zks%40mpf-ESPRIMO-P9012/T/)。
报告的芯片、固件完整版本 `WLAN.WBE.1.6-01270-QCAHKSWPL_SILICONZ-1`、
管理发送断言位置以及连接阶段故障与本机吻合，报告者还观察到其它平台在关闭
TX encapsulation offload 后恢复工作。**这是值得验证的线索，不是本机已经
证实的根因，也不是已经存在可直接照搬的最终修复。** 报告平台与 CS-06 不同。

当前源码 `wifi7/dp_tx.c:ath12k_wifi7_dp_tx()` 对初始未加密 EAPOL 和普通
Ethernet-offload 数据使用不同封装/HTT metadata 路径；已有补丁 115 主要修
已加密 EAPOL/GTK rekey，不能因补丁名称含 EAPOL 就认为初始握手已获得完整验证。
闭源的管理发送模块断言也不能单凭文件名排除 EAPOL 转交固件的可能。

下一步应在 **CS-06 范围、保持内核/CMA/MLO/加密/带宽等其余变量不变** 的条件下，
先对照 TX 封装卸载，记录 WPA/EAPOL 1/4–4/4 的实际收发及 TX completion。
Direct Switch 是否相关须另作单变量对照，不能同时关闭多个路径后宣称找到根因。
2.4G 应先在 5G 不触发崩溃的窗口单独检查握手与实际加密配置；无需索取用户密码。
本包没有 EAPOL pcap、hostapd DEBUG 或配置，尚不能确认停在第几次握手、密码是否
匹配，也不能把 2.4G 失败与 QCN9274 断言强行归成一个已证实原因。
