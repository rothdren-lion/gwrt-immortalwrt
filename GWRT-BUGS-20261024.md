# GWRT bug record — 2026-10-24

No firmware was compiled for these notes. Source changes only.

## 1. Firmware version must be `gwrt YYMMDD-NN`

Current live system after the theme fix:

```text
theme-version: 2026.10.24-01
top card fallback: gwrt 260903-06   (stale hard-coded fallback)
SSH banner: ImmortalWrt SNAPSHOT + Theme 2026.10.24-01
```

Desired firmware version format:

```text
gwrt 261024-01
```

- `261024` is the build date (`YYMMDD`).
- `-01` is the first build on that date.
- The next build on the same date is `-02`, then `-03`, etc.
- A build on a new date starts again at `-01`.

Source changes made (not compiled):

- Added `root/usr/share/gwrt/firmware-version` with `gwrt 261024-01`.
- Dashboard reads that file and uses it for the firmware card fallback.
- SSH banner reads that file instead of `DISTRIB_ID` + `SNAPSHOT`.
- Added `scripts/gwrt-next-firmware-version.sh` to increment the daily build
  suffix before a build.

## 2. Second card: SoC model and CoreMark

The second dashboard card (`CPU · NSS · PPE · 温度`) currently reports the
**device model** text, e.g.:

```text
AN7581 · 4 cores
```

Desired:

```text
AN7581*4
```

- The SoC row must come from the SoC / device-tree compatible value
  (`airoha,an7581`), not from the Nokia board model.
- Core count is the number of `processor` entries in `/proc/cpuinfo`.
- The format is SoC name, `*`, core count.

CoreMark:

- `/bin/coremark`, `/www/cgi-bin/coremark`, `/usr/libexec/gwrt-coremark` and
  `/etc/bench.log` exist on the live system.
- `ubus call luci getCPUBench` returns a score
  (`CpuMark : 15892.461014`), so the score source works.
- The CGI `status` branch returned plain `running`/`idle`, while
  `pollCoremark()` calls `response.json()`. A clicked benchmark therefore did
  not complete in the UI.
- The source now returns JSON from the status branch, loads the score through
  `rpcD`, and binds the `CM` label as well as the score to the run action.

Source changes made (not compiled):

- `renderSocSummary()` -> `label + '*' + cores`.
- SoC fallback no longer uses `board.model`.
- CoreMark CGI status -> `{"stdout":"..."}`.
- `CM` label is clickable and has an accessible title/role.
- `pollCoremark()` accepts `stdout`/`status` and handles fetch errors.

## 3. Network interface strip layout

Current behavior divided each group by `flex:1`, so the card width changed
with the number of detected ports, and the desktop row stretched every card
to fill the row.

Desired behavior:

- Cards keep a readable width (about 220px preferred, 168-260px range).
- The browser viewport decides how many cards fit per row.
- Do not divide the row by the number of actual ports.
- No horizontal scrolling on narrow screens; wrap instead.
- On phone widths, one card per row is acceptable.

Source changes made (not compiled):

- Removed the `gwrt-port-group` wrappers from `renderPortStrip()`.
- Added a final responsive CSS override:
  - `display:grid`
  - `grid-template-columns:repeat(auto-fit,minmax(200px,1fr))`
  - cards capped at `max-width:260px`, centered in their tracks
  - single full-width card below 420px
  - no horizontal overflow
- Theme left based on the 192.168.9.9 `1.0-r111` source; cache-buster set to
  `20261024r02` so a future build cannot serve the old CSS.
- Static browser layout check (5 cards, no firmware build):
  - 1600px: 1 row, 260px cards
  - 1200px: 1 row, 227px cards
  - 800px: 2 rows, 251px cards
  - 520px: 3 rows, 240px cards

## 7. Current image health check (2026-10-24, after flash)

The existing image boots and is usable, but these are the remaining known
issues / limitations:

1. **lan1 MAC / FE hardware forwarding warning**
   - `lan1` (gdm4) got a random MAC `16:9e:b3:1b:c2:9a`; `eth0` correctly
     has the factory base `26:c4:18:c7:0b:69`.
   - dmesg:
     ```text
     airoha_eth ...: eth1: wrong mac addr, MSBs must be 26:c4:18
     airoha_eth ...: FE hw forwarding won't work properly
     ```
   - Root cause in source: gdm4 used `macaddr_factory_3e (0)`, same as
     gdm2/WAN; gdm1 uses `(1)`.  Source is now corrected to `(2)`, but the
     running image still has the old DTB.  This needs the next image rebuild.
   - Hardware forwarding / NPU acceleration should not be considered fully
     verified until that DTB is flashed.

2. **WireGuard / Docker / Podman kernel support** remains pending.  The
   current running kernel predates the new KCONFIG; WireGuard's
   `udp_tunnel.ko` fails on missing GRO symbols.  Docker/Podman module set is
   not enabled in the running image.

3. **sysupgrade wipes the overlay** (confirmed).  After flashing the base
   image, add-ons/theme/modules must be reinstalled with
   `addons/install-addons.sh`.

4. **OAF vs NPU/flow offload** is a policy conflict, not a crash.  Current
   default keeps `flow_offloading=1`/`hw=1` and `disable_hnat=0`; OAF cannot
   fully inspect offloaded flows.  Disable HNAT/flow offload when filtering.

5. **No PON optical signal / no default route** at the time of testing.
   `pon0` is down, so WAN and online-app tests cannot be completed.  AOF
   dashboard showing 0 users/traffic is expected.

6. **USB** controllers are enabled; no USB device was enumerated.  NTFS3 is
   now loaded.  OpenWrt does not auto-mount by default.

7. **CoreMark** shows `N/A` on a fresh flash until the top CM is clicked or
   `/etc/coremark.sh` is run.  Current run: 15531.
